# DiPlay Tesla 0.1.3 — V50 无线连接修复（本地测试）

V50 的系统管理服务占用了 8080，导致原先固定端口的 DiPlay 浏览器服务无法启动。本版在绑定失败后依次尝试 8080–8089，连接页和复制的链接使用实际端口；其他启动错误保留原错误，不进行端口重试。没有停止或修改固件的管理服务。

本地 V50（Android 13）已安装含此前配置的 MFi 资产的签名 APK，应用启动和认证资产加载成功，浏览器服务实际使用 8081。无线握手确认 iPhone 接受 MFi 认证；网桥修复后，电脑浏览器已收到真实的 1024×768 H.264 / WebRTC CarPlay 画面。

热点选择增加实际网桥成员证据：当 Wi-Fi 热点的 IPv4 地址在网桥上时，优先使用该网桥地址，保留上游网络排除和稳定性检查。V50 的 `br0` 包含 `wlan1`，无需应用 root 或硬编码网桥名称。基础功能、浏览器输出和独立 proxy 的边界保持原设计；proxy 上游需填写主机的实际端口。

无线重连时，每次 WebRTC 报价现在使用跨输出实例唯一的编号，避免旧输出异步发送的停止消息或反馈影响新输出。回归测试覆盖旧会话命令不能停止新视频。修复版在 V50 上完成全屏 → 右侧 → 全屏切换，1024×768 和 1920×1080 都在确认重连后直接恢复 WebRTC，无需刷新网页，切换时观察到约 21–23 fps、丢帧为 0。静止页面帧率降低不代表连接中断。

完整 AGENTS.md CI、相关 lint 和最终签名构建通过，2260 项单元测试零失败。实际浏览器主页按键和打开音乐应用的触控已验证，虚拟按键恢复隐藏。保存配置和取消重连保持原连接；确认重连后使用全屏配置。浏览器音频已开启，但仍需收到实际音乐数据并检查听感。这些结果来自 V50 与电脑浏览器，尚未进行 Tesla 车内测试。此 APK 尚未公开发布。
