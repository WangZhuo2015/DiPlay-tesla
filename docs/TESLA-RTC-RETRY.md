# JPEG 回退后的 WebRTC 有界重试

本改动适配 WheelPlay
[`44635dd94e95fed6a8973faf85437c8a9342e44a`](https://github.com/fython/wheelplay/commit/44635dd94e95fed6a8973faf85437c8a9342e44a)
的重试策略（GPL-3.0），沿用 DiPlay Tesla 独立 `browser` 模块、单个认证媒体所有者和既有 H.264/JPEG 路线，不移植其 `LanWebServer`。

## 行为

- 自动 WebRTC 模式在临时失败后恢复 JPEG，并于 **5、10、20、30 秒**后重试。继续失败时保持 **30 秒**间隔；限制的是重试频率，不是整个连接的总尝试次数。只有一个 RTC 尝试进行中。
- Android 的单个 RTC worker 和单调时钟负责重试。网页不另外建立 RTC 重试计时器，也不因此重连音频 WebSocket 或 iPhone。
- JPEG 在冷却和新 peer 协商期间继续可用。只有浏览器确认新视频实际开始播放后，才暂停 JPEG 解码；旧 peer 的回调、SDP Promise 和旧 ID 指令不能停止新 peer。
- 新 peer 一度显示画面不会立即清零退避。连续健康显示 **60 秒**才恢复到首档；断连、发送/解码恢复状态会重新计算这段健康时间。源画面静止但正常回报状态不算失败。
- 浏览器明确的 `NotSupportedError`、SDP 禁用视频，或 Android 原生传输库不可用、无效视频配置，停止当前媒体连接/视频配置的自动重试。其他协商和连接失败仍按退避处理。`NotAllowedError` 仅表示当次播放上下文/用户激活受限，不视为永久不支持；之后允许播放时可恢复。并不把所有协商错误都误当永久不支持。
- JPEG 内部重新协商和再次失败不切换显示路线，也不取消正在进行的拖动/长按。真正的 JPEG/WebRTC 显示切换或控制连接结束仍释放触摸，避免旧画面坐标留在新显示或旧连接中。
- 媒体连接关闭、页面隐藏/离开、切换到 JPEG 或更改视频配置会取消旧尝试和冷却；重新进入/连接或新视频配置使用新的重试预算。原有媒体所有权、约五秒的 WebSocket 心跳和音频背压断开规则不变。
- 现有 **4/10/30 秒恢复等待**仍是单次 RTC 尝试遇到问题后的等待期限，与回退后的 **5/10/20/30 秒重试退避**分开，不增加视频或音频缓冲。

## 验证边界

新增测试覆盖退避边界/上限、重复失败、健康一分钟/恢复间隙、永久拒绝、重新配置/断开取消、旧 peer 隔离、JPEG 协商期间保持可用、网页永久错误上报和旧异步失败。

本地源码和合成测试结果以本轮最终验证记录为准；没有新增 Tesla/iPhone 实车验证。不能保证网络尚不可达、Tesla 固件不支持解码或页面权限被拒绝时恢复 WebRTC。
