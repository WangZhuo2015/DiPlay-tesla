# 新版主机界面（开发中）

这份说明对应尚未发布的主机界面改版。Android 主机首页、首次配置、Tesla 网页菜单采用同一套深色卡片、浅蓝操作按钮和声音控件。

## 日常使用

1. 打开 Android 上的 DiPlay Tesla。首页分别显示 iPhone 与浏览器的连接状态。
2. 点击 iPhone 卡片，可以选择手机、通过无线或 USB 连接，或断开正在运行的会话。
3. 在 Tesla 浏览器打开首页显示的地址，输入六位配对码。复制地址按钮只复制入口地址；配对码留在主机屏幕上。
4. 配对码五分钟过期，输错五次后也需要在主机上点击“重新生成连接码”。刷新状态、切换页面不会自动延长有效期或清除错误次数。
5. 网页顶部把手打开菜单。音乐、导航音量放在前面；主机导航衰减和缓冲位于“高级音频”。显示设置继续保留独立的右侧／全屏配置。

浏览器已连接表示已通过认证并建立媒体连接，不代表实车画面、声音或网络质量已经验证。

## 首次配置

首次配置分为四步：准备 Android 主机、连接 iPhone、选择浏览器入口、配对浏览器。权限和自动连接选项沿用原有设置。不会再询问 DiLink 车型代际。

“浏览器入口”接受 HTTPS 域名地址，可包含端口，不接受路径、账号密码、查询参数或配对码。保存入口不会断开当前 CarPlay 会话。

## 代理与内网限制

APK 自身仍提供 HTTP 服务。仓库的 [Node 网关](../proxy/README.md) 与 [Android root / Caddy 方案](../proxy/android-root/README.md) 独立部署；APK 不会安装、启动或维护它们。

界面中的“HTTPS 入口已配置”只表示保存了入口元数据。证书、DNS、网关进程、路由与实际可达性需要另行配置和验证。

部分 Tesla 固件会限制 RFC1918 内网地址。域名仍解析到受限内网地址时，增加域名或 HTTPS 不保证可以访问。具体背景见[内网 IP 访问限制](TESLA-QUICKSTART.zh-CN.md#tesla-内网-ip-访问限制)。

网页经 HTTPS 网关打开，也不代表 WebRTC 的媒体通路可达。车机屏蔽内网地址时，媒体同样需要车机可达的候选地址或独立中继；当前 HTTPS 网关不会自动中继 UDP。

## HEVC 与视频传输

开发中的 Tesla 版本默认允许 iPhone 协商 HEVC，并保留 H.264 支持。已经明确保存过的 HEVC 开关继续按原值执行。开关位于 **高级 → HEVC 视频（实验性）**，下次 CarPlay 连接生效，保存不会主动断开会话。

H.264 和 HEVC 都直接转发 iPhone 的压缩码流，Android 负责参数解析与 RTP 封包，不解码、不重编码。实际格式由收到的码流确认；浏览器状态显示实际的 H.264／HEVC。

车机浏览器必须支持对应的 WebRTC 视频格式。HEVC 不被接收端支持时会显示提示，应在 Android 关闭 HEVC 后重新连接 CarPlay；不会在 V50 上将 HEVC 转为 H.264。

默认 WebRTC 模式不再自动回退 JPEG，也不会在等待首帧或恢复连接时轮询 JPEG 接口。JPEG 保留为 **显示设置 → 手动调整 → 视频传输 → JPEG（手动排障）**，只支持 H.264，需要显式选择。HEVC 会话下不会启动 JPEG 解码器。

“JPEG 画质”只控制手动 JPEG 模式的图片压缩质量，不控制 iPhone 的 H.264／HEVC 编码质量。以上行为属于开发预览版，已发布版本的行为以对应版本说明为准。
